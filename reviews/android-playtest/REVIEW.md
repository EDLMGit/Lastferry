## First-run findings and test limits

The initial Java build found a collision with Activity’s existing fullscreen method. While reviewing first-frame readiness, we also replaced a one-shot page-load check with a bounded foreground wait for the renderer. The original CLI launcher failed to rename a Windows cache directory, so SDK installation used the pinned 19.0 command-line tools. The web regression uses an explicitly reachable localhost preview. Vite retains its existing bundle-size advisory. During concurrent emulator and browser work, one pre-existing Two Shelters geometry test exceeded its 30-second limit (775/776). Running the entire suite serially passed 776/776 with the original timeout.

The first installed checks exposed the background-audio defect described above. A driver expected “Bellwater” where the UI said “Bellwater Cove.” The corrected assertion observed the original earned save. A fixture loaded immediately before a force-stop did not reliably reach the intended final cove. The successful fixture run reloaded the local page, asserted the level and played it. Early post-update Home and Practice screenshots briefly showed the same Android compositor frame. The settled phone images linked above were recaptured and visually inspected. [Original failures and corrected observations](play/README.md)

The emulator showed uneven frame pacing under automation and screen capture. Android reported 645 missed frame deadlines out of 1,351 sampled, with a 48 ms median and 109 ms 95th percentile. A physical phone is still needed for touch feel, sustained performance, speaker balance, TalkBack and the uncoached first rescue. The minimum Android/WebView versions are compatibility bounds. The installed-device run used the versions listed above. [Performance sample](device/final-device-sample.json)
