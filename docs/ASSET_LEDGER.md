# Last Ferry asset provenance and history

Runtime geometry and synthesized audio are original code authored for this project by Codex, starting on 2026-10-20; later additions are dated below. Original local SVG icons and CSS surfaces from the supplied cove package join this family in the current pass. No third-party model, image, recorded audio, remote icon or font download is loaded by the game. System-installed fonts and the Three.js library keep their own rights. Project sources remain subject to the project's chosen rights; this ledger does not assert a new distribution license.

The subsequent panel refinement uses the original CSS and sparse shoreline SVG supplied in `cove-panel-package/material/`. These are editable code-native sources authored for this project in ChatGPT, with no acquired image or generated bitmap texture. The material CSS is the single runtime source, adapted for the existing shared selectors and focus rules; its sibling SVG remains the decoration source. See the package [`README`](../cove-panel-package/README.md) and [`material contract`](../cove-panel-package/material/MATERIAL_SPEC.md). The standalone HTML/PNG/SVG boards are design references, never gameplay evidence.

The canonical current inventory is [`assets/catalog.json`](../assets/catalog.json). It records reusable families, exact source paths, provenance, lifecycle, per-type detail, acceptance and evidence. This ledger preserves authoring history rather than maintaining a second current inventory. The development gallery at [`asset-gallery.html`](../asset-gallery.html) reads that catalog and the actual shared component/icon sources; its specimens are design evidence, not gameplay screenshots. Run `npm run check:assets` to check the inventory. Add, replace or retire a family in the same change as its catalog/gallery/provenance entry; reuse existing families first.

The summary below was originally established for M1; source pointers for sound and system fonts are corrected to the current implementation. Later records describe their historical milestone and do not assert that every old treatment remains current.

No external or generated bitmap asset was added. Shared water remains the existing shader; the broader water/shore treatment is deferred to the next milestone. Fresh gameplay evidence is under `reviews/bellwater/`.

Shared environment milestone (2026-10-22): original procedural geometry and materials in `src/scene/paths.ts`, `motion.ts`, `shore.ts`, `water.ts`, `effects.ts` and `world.ts` replace raw route polylines, repeated water highlights and layered coast rims. Bounded corner fillets supply one cached course for drawing and motion. A generated 256×256 data texture describes coastal banks and submerged ground; it is created locally from level geometry, not downloaded or generated concept art. Coast lofts, instanced rock/reed groups, water-height wetness/contact and cached forecast contours retain the validated footprint envelope. A short dynamic stern wake and the existing lighthouse lens/lamp response add restrained travel and arrival detail. Ferry, passenger and landmark models remain the established asset family. No external model, image, font, recording, license or dependency was added. Evidence and matched comparisons are under `reviews/environment/`; historical captures retain their original sources.

Atmosphere milestone (2026-10-22): original `seabed.ts` authors one bounded 256×256 linear albedo/height field from shore contours, fixed irregular elliptical sand/rock patches and deterministic low-frequency variation. It is distinct from the retained 256×256 coastal mask. `water-shader.ts` authors compatible analytic normals, composed sky light, view-ray substrate distortion/absorption and the existing lamp's amber reflection. Two RGBA textures total 524,288 bytes, generated once per cove; no downloaded normals, environment maps or reflection captures. Installed Three.js tone/output shader chunks are MIT library code; no third-party shader was copied.

Original cue “Between the lamps” is authored in `src/audio/score.ts` and synthesized by `atmosphere.ts`: 64 BPM, 80 beats/75 seconds, ten open voicings and 21 explicit motif notes/rests. Reproduce with the score's MIDI pitches/durations, two locally generated periodic waves, deterministic 8-second mono filtered-noise buffer (seed `0x52f34321`) and 3.6-second stereo impulse response (seed `0x126abe31`). At 48kHz these reusable PCM buffers total 2,918,400 bytes; no encoded runtime recording is shipped. One shared reverb supports the music; owned action tails allow precise Undo cleanup. The emotional reference was tenderness, air, wonder and longing; no AURORA melody, recording, lyrics or sample was used. No external model, image, font, music, code asset or dependency was added. Actual-runtime media and listening limitations are attributed separately under `reviews/atmosphere/`.

Shallow-detail refinement (2026-10-22): original precomputed contour fields, compact coast-connected sand tongues/angular stone forms and broad linear albedo variations replace the earlier soft patches inside the same two 256x256 RGBA fields. Original island vertex colors and scoped world-height contact materials add restrained sand/stone/grass/wet distinctions without new geometry or assets. The lighthouse model now exposes its existing lens/lamp/anchor and keeps a steady warm baseline. No downloaded textures, added props, reflection target, extra render pass or new dependency.

Selection presentation (2026-10-22): original DOM/CSS compact place markers and one translucent action card; existing rocky scenery substituted at Holding's Stone island. The lighthouse's locally authored lens/core, slightly opened roof and scoped warm gallery/upper-tower/underside materials make its source visible with normal occlusion. Existing light/glow/reflection ownership remains local. No external model, image, font, recording, texture, dependency, asset pipeline or additional scene pass was introduced.

The bounded accompaniment in `src/audio/arrangement.ts` authors two compatible pitches for each of the ten accepted harmony cells, synthesized through the existing soft palette and music reverb. Early/late notes share pitches with the overlapping neighboring pad cells. The accepted score and buffers remain byte-identical. See `docs/AUDIO.md` for state derivation and playback behavior; actual runtime recordings and listening limitations remain separate in `reviews/refinement/`.
